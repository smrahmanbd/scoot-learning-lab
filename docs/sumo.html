SUMO code

    SCOOT in SUMO

    A SCOOT-style controller in Python that drives Eclipse SUMO through TraCI. Every second it reads the upstream detectors, updates each link's profile and queue model, and runs the split, offset and cycle optimisers. It writes logs and figures for every lab on this site.

    Install and run

    Python 3.9 or newer. SUMO itself installs from pip (a system SUMO with SUMO_HOME set also works).

    git clone https://github.com/smrahmanbd/scoot-learning-lab.git
cd scoot-learning-lab/sumo
python -m pip install -r requirements.txt      # eclipse-sumo, traci, sumolib, numpy, matplotlib, pytest

python foundation/03_fixed_vs_scoot.py --gui   # watch SCOOT in sumo-gui
python run_all.py                              # every lab, about 15 minutes
python tools/export_site_results.py            # copy figures and tables into the website
python -m pytest tests -q                      # unit tests

    Every script accepts --gui, --seed, --end (demand duration in seconds) and --out. Results go to sumo/results/<level>/.

    The test network and detectors

    network.build_corridor(n, spacing) builds an east-west arterial with n signalised junctions and a side street at each. Every link entering a junction gets two kinds of loop on every lane:

    up_<lane>
    the SCOOT detector, 30 m after the start of the link (about 270 m before the stop line on the main road, 170 m on side streets).
    loop_<lane>
    a stop-line loop, used only by the actuated baseline and to check SCOOT's model against SUMO.

    Each junction runs two stages: A for the main road (left turns permissive) and B for the side road; intergreens are 3 s amber plus 2 s all-red.

    The link model, every second

    # scoot/controller.py - Link.step()
m = self.measure(t, tau, det_data)          # LPUs at the upstream detector this second
self.buf.append(m); src = self.buf.pop(0)   # lag of beta * cruise time
self.arr = F * src + (1 - F) * self.arr     # Robertson dispersion -> stop-line arrivals
self.q += self.arr                          # arrivals join the queue
if eff_green:
    self.q -= min(self.q, self.sat)         # discharge at saturation occupancy
self.cyc[tau] += self.arr                   # build this cycle's profile

    At the end of each region cycle the profile is smoothed (prof = 0.75 prof + 0.25 this_cycle). DoS for a link is (sum(prof) + residual) / (effective green × SATO), raised by the congestion importance factor when the detector shows standing traffic.

    The optimisers

    # Node.split_optimiser(k)   - 5 s before stage change k
opts = core.split_options(change_times, k, intergreens, min_greens, C, authority=4)
dos  = {d: self.max_dos(C, extra=d at k) for d in opts}
d    = core.choose_split(dos)              # lowest max DoS, ties keep
temp[k] += d                               # this cycle only
change[k] += sign(d) * 1                   # permanent drift

# Node.offset_optimiser()   - once per cycle
pi = {d: self.offset_pi(C, d) for d in (-4, 0, +4)}   # queue model on links in and out
change = [c + core.choose_offset(pi) for c in change]

# Region.cycle_optimiser()  - every 300 s (150 s while rising)
candidates = C - step, C, C + step (+8/12/16 s if critical DoS > 0.9)
feasible   = predicted critical DoS <= 0.9 (<= 0.8 for shorter cycles)
choose     = smallest increase if over target, else the feasible cycle with lowest PI

    Using your own network

    1. Build or import a network with netconvert (for example from OpenStreetMap), with the junctions you want as traffic_light.
    2. Add an inductionLoop named up_<lane> near the upstream end of every incoming lane, and record each link's detector-to-stop-line distance.
    3. Define each node's stages and minimum greens; the lab uses two stages, and more stages need extra change times in Node.
    4. Validate: run foundation/02_validate_model.py, adapted to your links, to set SATO, lags and cruise speed.
    5. Group nodes into regions where coordination matters.
